Versioning & Release Management

Starting with JAZB v3.0.0, the unified Framework uses a three-component version identifier. The version communicates the component revision history, while the full publication date identifies when an edition was released.

Cumulative versioning. A component number is never reset merely because another component changes. For example, if v3.0.1 is released first, the next Core-only update is v3.1.1, retaining the previously issued XAA revision. Bold numerals above highlight components changed relative to the v3.0.0 baseline.

Latest publication first. Releases are presented newest to oldest by their actual publication date, not by comparing version suffixes. Every new publication entry states the full Month Day, Year release date, complete version, change classification, summary and permanent DOI. VTT results remain tied to the exact edition evaluated.

Publication lineage: Earlier Framework v1.x/v2.0 and Enforcement v1.0 editions retain their historical version identifiers. The three-component RELEASE.CORE.XAA convention starts with unified v3.0.0. Where a predecessor record only gives a month, the original date precision is retained until its precise day can be confirmed.
