AI Governance & Enforcement

v3.0.0 · October 31, 2026

Replaces Framework v1.0 to v1.4, v2.0 and Enforcement Framework v1.0 with one unified framework for governing what enterprise AI is authorized to do. It is a replacement, not an upgrade: earlier editions stay citable but are no longer the reference.

  • One institution, always present: the Governor (human-established Law), Judge, Commissioner, Commandant and Inspector, independent actuation, and Border Jurisdiction.
  • Two operating options. In Core Operation, the AA prepares work but never executes it, so a person applies it and stays responsible. In optional XAA-Enabled Operation, the XAA executes pre-enrolled transactions within thresholds the EDA sets.
  • The AI is never given execution rights. Elevation goes to the user’s own account through the Judge and ends when the Inspector reports the task complete.
  • Actions the Law does not define are paused for a one-off human Approve or Deny decision, which never becomes standing Law.
  • Border Jurisdiction (Enterprise AI Customs): data leaving or entering the organization needs its own authorization, layered on existing security tools. Lawful possession is not lawful passage.
  • Five parts, 23 chapters, 195 normative requirements and 77 verification scenarios, with RELEASE.CORE.XAA version identifiers.

VTT-001 and VTT-002 were replayed against v3.0.0; see Research.

Cybersecurity Framework

Core v1.2.0 · November 11, 2026

Moves the framework from cybersecurity control assurance to governed enterprise assurance. Where v1.1.1 expanded cybersecurity coverage and assessment depth, v1.2.0 adds governing-body accountability and independent governance verification.

  • New Governance Core: 13 governance outcomes (G01 to G13), each with assessable components, checks, linked requirements, standards relationships and audit questions.
  • Applicable governance outcomes must be independently assessed and Verified to support a conformance claim.
  • Design principles, governance and implementation roles, organizational profiles, gap analysis, overlay and extension rules, and maintenance provisions.
  • Governance crosswalks to NIST CSF 2.0 Govern, NIST AI RMF, ISO/IEC 27001, ISO/IEC 42001, COBIT 2019 and governing-body duties in law.
  • All 172 requirements and 420 acceptance checks preserved, with identifiers and statements unchanged.

AI Extension v1.0.0 is released separately, with its own version and documentation.

Version integrity

Versions are family-specific.

Each framework family has its own version format. Neither inherits the other's rules.

AI Governance & Enforcement: RELEASE.CORE.XAA

Three cumulative, independently tracked counters: framework generation, common Core revisions, and optional XAA revisions. They are not conventional semantic-versioning major, minor and patch numbers.

RELEASE · First number

3 → 4

Advances when a new major generation of the unified AI Governance & Enforcement Framework is issued. Example: v3.0.0 → v4.0.0.

CORE · Second number

0 → 1

Advances for changes to common Core requirements or functionality. Example: v3.0.0 → v3.1.0. An XAA counter already advanced is retained.

XAA · Third number

0 → 1

Advances for changes limited to optional XAA requirements or functionality. Example: v3.0.0 → v3.0.1. A Core counter already advanced is retained.

Versioning rules

Increments are retained within a framework generation

Starting at v3.0.0, an XAA-only revision produces v3.0.1. If a Core-only revision follows, the resulting identifier is v3.1.1, not v3.1.0, because the previously published XAA revision remains in effect. The v3.1.0 and v3.0.1 examples above illustrate different possible first updates from v3.0.0, not a mandatory release sequence.

Simultaneous changes: A single release changing both Core and XAA advances both counters, for example v3.0.0 → v3.1.1.

New framework generations: Advancing RELEASE resets both CORE and XAA counters to zero, for example v3.1.1 → v4.0.0.

Editorial corrections: Corrections that do not change normative meaning, applicability, Authority, enforcement behavior, or assessment expectations retain the same version identifier. They are issued as a dated corrected edition, recorded in the release notes, with the original edition preserved for traceability. Changes that affect those matters require a numbered release.

Each published edition retains its own version identifier and publication date, displayed as Month Day, Year. Current editions appear before historical editions, which remain separately citable. Changes to normative obligations require controlled revision, corresponding acceptance testing, applicability review, and explicit version attribution.

Cybersecurity Framework: MAJOR.MINOR.REVISION

The Core (currently v1.2.0) and the AI Extension (currently v1.0.0) each keep their own version history. A revision to one does not change the other's version. Cite each component by its own version and Zenodo record.

Terms used on this page

Core Operation
The complete configuration, in which people carry out every consequential action.
XAA-Enabled Operation
The optional configuration that adds the XAA for specific, pre-enrolled transactions.
AA
AI Assistant. An AI AGENT that helps end users but does not execute consequential changes.
XAA
Executive AI Assistant. An AI AGENT authorized to carry out specific consequential tasks, within the limits the EDA permits. Present only in XAA-Enabled Operation.
EDA
Enterprise Domain Authority. The human sovereign root of a JAZB organization; every other Authority traces back to it.
Law
The rules people establish through JAZB governance, defining what any actor, human or AI, may do.
Authority
Legitimate, human-established permission to act. Access, credentials and technical capability do not amount to Authority.
RELEASE.CORE.XAA
The AI framework’s version format: framework generation, then common Core revisions, then optional XAA revisions.
MAJOR.MINOR.REVISION
The Cybersecurity Framework’s version format. The Core and the AI Extension each keep their own.
