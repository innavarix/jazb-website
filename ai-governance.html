Publication-specific versioning

How JAZB v3.0.0 is updated

The AI Governance & Enforcement Framework uses RELEASE.CORE.XAA. These are cumulative, independently tracked framework-generation, common-Core, and optional-XAA revision counters. They are not conventional semantic-versioning major, minor, and patch numbers. This scheme applies to this framework, not the separately versioned JAZB Cybersecurity Framework.

RELEASE · First number

3 → 4

Advances when a new major generation of the unified AI Governance & Enforcement Framework is issued. Example: v3.0.0 → v4.0.0.

CORE · Second number

0 → 1

Advances for changes to common Core requirements or functionality. Example: v3.0.0 → v3.1.0. An XAA counter already advanced is retained.

XAA · Third number

0 → 1

Advances for changes limited to optional XAA requirements or functionality. Example: v3.0.0 → v3.0.1. A Core counter already advanced is retained.

Cumulative versioning example

Updates do not erase earlier increments

Starting at v3.0.0, an XAA-only revision produces v3.0.1. If a Core-only revision follows, the resulting identifier is v3.1.1, not v3.1.0, because the previously published XAA revision remains in effect. The v3.1.0 and v3.0.1 examples above illustrate different possible first updates from v3.0.0, not a mandatory release sequence.

Each published edition retains its own version identifier and publication date, displayed as Month Day, Year. Current editions appear before historical editions, which remain separately citable. Changes to normative obligations require controlled revision, corresponding acceptance testing, applicability review, and explicit version attribution.
